# T01：最小怪物配置可校验

唯一目标：建立战斗原型所需的最小怪物配置，并在 Unity 中准确发现无效配置。

规则依据：GDD 第 0 节单目标和证据原则、第 8.2 节占位怪物、第 11 节只读配置/稳定 ID/配置校验；DEVELOPMENT 任务板 T01。开始前已读取 AGENTS、STATUS、最近任务 R02、相关 GDD、现有代码及 Git 状态，工作区干净。

范围：UnitDefinition 仅包含稳定 ID、显示名、移速和穿门伤害。三份占位样例 U01/U02/U03，速度是可调整试验参数，穿门伤害沿用 GDD 的 1/2/4。新增校验菜单、幂等样例创建工具、构建前校验与 Edit Mode 测试；使用现有测试框架，不升级或新增包。

验收：

1. 合法的已保存配置可被 Unity 发现并通过校验；运行时仅有读取属性，不提供修改配置接口。
2. 缺失/重复 ID、空显示名、非正数或非有限移速、非正整数穿门伤害可被检出，指出资产路径、字段和原因；重复 ID 提示冲突双方。
3. 校验不修改资产，不默默修正数据；重复创建样例不重置人工值或 GUID。
4. 构建入口执行同一校验，非法配置阻止构建。
5. 在 Unity 实际运行合法/非法两类 Edit Mode 测试，执行项目配置及入口检查，构建和启动必要的回归；纳入 `.meta`，提交本地 Git。

排除：怪物移动/路径/生成、HP/攻击/战斗、部署次数与 CD、商店、羁绊、升星、正式美术及新框架。

设计连接：Inspector 修改 ScriptableObject → 编辑器扫描配置 → 诊断/构建拦截；后续 T02 通过 UnitDefinition 只读属性读取初始数值，位置等状态单独保存。本任务不创建运行时单位。

状态：已完成。Unity 实际创建并校验三份样例；17 项 Edit Mode 测试全通过；重复生成哈希不变；Windows 构建和 Player 启动通过。实际证据见 QA / `verification/T01.json`。未人工操作 Inspector/菜单，未运行 Play Mode/移动/战斗测试或第二机验证。
