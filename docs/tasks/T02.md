# T02：单只怪物沿固定路线移动

唯一目标：一只占位怪物读取 UnitDefinition 移速，沿场景固定路点移动并准确停在终点。

依据：用户“开始 T02”；GDD 6.2 统一模拟时间、6.3 固定路点、8.2 占位参数、11 配置与状态分离；T01 配置接口。开始前已读 AGENTS、STATUS、T01、CONFIGURATION、GDD 对应段、现有工具和代码，Git 状态干净。

验收：

1. 入口 Play 后只有一只原型单位，读取 U01 的 1.5 世界单位/模拟秒，沿折线路线逐点前进；路线/怪物/终点可见。
2. 跨路点保留本步剩余距离，大步不越过终点；到达后保持终点，不循环、不生成第二只单位。
3. 路线为固定路点快照，不使用物理碰撞或动态寻路；运行位置不写回配置。模拟 delta 为 0 时不移动。
4. 缺失引用、无效路线可定位并拒绝验证/构建；生成工具幂等，已有场景内容和 GUID 不被重建。
5. 实际运行 Edit Mode 算法/边界测试、Play Mode 场景测试、Windows 构建与端到端移动烟雾检查，保存截图和日志，提交 Git。

范围：最小移动状态、单位表现、单一时间驱动、入口场景中演示路线、必要生成/校验/测试和证据。正移速沿用 T01；路线长度与位置为试验布局。

排除：DP/部署交互、多怪生成、蓝门伤害或穿门事件、战斗/阻挡/攻击、暂停 UI、重试系统、商店、美术制作。终点蓝色标记只是位置标记，T03 才结算蓝门。

状态：已完成。34 项 Edit Mode、3 项 Play Mode 全通过；实际 Windows 构建与完整路线移动通过；主相机起点/中途/终点图片已查看；重复生成未改变场景/材质/meta。实际结果见 QA 与 `verification/T02.json`。

未执行：人工 Inspector/UI 点击、完整 OnGUI 画面验收、第二机验证；无蓝门伤害或其他战斗测试。Player 暴露的浮点进度漂移已由固定步长测试复现并修复，保留失败证据。
