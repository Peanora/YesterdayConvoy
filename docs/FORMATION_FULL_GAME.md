# 棋盘完整挑战：运行与维护

本模式以用户于 2026-11-17 采纳的 [v0.7 完整设计](design/FULL_GAME_v0.7.md) 为依据，使用最新暖灰工业棋盘。原 Word、可检索正文与参数快照均在 `docs/design`。实际验证结果及构建对应提交以 [QA](QA.md) 为准；设计被采纳与运行验证是两个不同事实。

## 一局怎么玩

- 普通启动进入棋盘完整挑战；菜单保留旧玩法。开局独立随机三名不同一费，3级、8金币，先选基础装备，再选战略预案。预案可整组重抽一次。
- 23个节点包含20场战斗和3次补给，贯穿三个位面。所有常规战斗复用保存的 `Assets/Scenes/FormationBattle.unity`，不在运行时重建地形。
- 左侧 10×8 布阵，红门在第 10 列。右侧 10×8 守军区，蓝门在第 21 列。整图 22×8、176 个底格，坐标从 0 开始。两处高台和两处低掩体随守军阵形内移。棋盘两侧连续显示，备战用右侧箭头或 `V` 横移镜头，回到我方视角可在前沿平台领取奖励球。视角保持 60° 斜俯视，战斗采用右侧近全屏固定构图。
- 左下显示等级、经验及购买经验，右下金币按钮打开招募商店，上方小字显示真实规则下的预计利息。商店默认收拢，点击金币或按 `Tab` 切换，`Escape` 关闭。
- 准备期底部只有10格备战席；棋盘本体就是已上阵角色，没有第二条出战卡槽排。备战角色直接拖入棋盘部署，场上本体可拖回备战。重叠可合法交换，阵容与站位跨关保留；人口按角色数计，大体型仍只占一个人口。战斗和暂停隐藏全部备战、羁绊、金币/利息、经验与运营面板，仅留战场和简洁战斗HUD；不能买卡、改阵或重开运营面板。结算及下次准备自动恢复。
- 点击左侧羁绊查看人数、已激活档位与下一档条件，以及全部天然成员的上阵/备战/未拥有状态；转职成员单独显示。详情支持滚动与关闭，`Escape`优先关闭详情。不同种类按正式规则去重，备战成员不计入激活人数。
- “装备”管理不限数量的物品栏、三件装备槽、拆卸、固定合成与复制器；“军阵搭档”设置主C、同频和提词配对、接棒者、剧场主角、维维美技能与萨卡兹契约。未指定时使用合法推荐。
- 海嗣达到门槛后，可在右侧点格布置溟痕；区域须上下左右连通且不超过4/7/10格。清除手动格恢复推荐区域，开战前再次校验。
- “防线”查看守军实际生命、攻击、防抗、技力和技能；遭遇关还可选择1至4档，看到对应强度与奖励。进度严格大于25%才能领取额外遭遇奖励。
- 开战后自动移动和施法，我方阵亡原位等待复活，暂停冻结统一模拟时钟。必须全清守军后由存活本体实际进蓝门才胜利；召唤物不能替本体进门。奖励战不限时，普通/遭遇90秒，前两名首领120秒，终局150秒。
- 胜败都按规则结算基础5金、2XP及利息；普通/遭遇/首领胜利累计连胜，失败扣队伍生命。结算只领取一次，不能通过重试刷资源。队伍生命归零或最终关结算后结束挑战，可重新开始。
- 1-3、2-2、3-2战前选择战略战备；补给选包后直接继续，不触发战斗收入。奖励球、希望门槛、赠卡与复制器均走真实库存；缺货或满备战的奖励会待领。

## 数据与职责

`docs/design/parameters.v0.7.json` 是采纳版本的参数快照。`tools/generate_formation_rules.py` 从它生成 `FormationCampaignRules.cs` 的角色面板、羁绊、装备、预案与战备等数值。当前节点守军、阵型、难度与首领面板来自 `FormationDefensePlan.cs`，详见[棋盘守军难度与阵型](design/FORMATION_DEFENSE_CURVE.md)。调整技能倍率或触发规则时同步战斗实现和相关回归。

| 运行层 | 职责 |
| --- | --- |
| `FormationShopSession` | 卡牌席位与棋盘站位之间的真实投影，阶段交易锁，跨关同步 |
| `ShopTrialModel` | 有限库存、展示占库、三合一、升星、价格、经验、经济及奖励预占票据 |
| `FormationCampaignRun` | 节点、队伍生命、希望、预案、战略战备、装备和一次性奖励；塔露拉待抉择与待领队列 |
| `FormationBattleModel` / `FormationCombat*` | v0.7逐人技能、统一时钟、原生/补击/派生、羁绊、叠层、阶段、召唤与守军 |
| `FormationBattleController` 的界面/呈现分文件 | 原 A 商店、选择界面、备战侦察镜头和实际动作／命中特效 |
| `FormationUnitCatalog` / `FormationUnitArt` | 原43张和19张新增Boss的兼容身份、占地及真实动作来源；正式招募池由Rules的46人限定 |

兼容目录的旧卡费用/Stats用于旧测试与旧模式，不用来覆盖正式店的v0.7费用。正式模式直接读取Rules，塔露拉当前费用则读取本局商店状态。旧构造 `FormationShopSession(seed)` 是原无限金币样板，完整入口显式使用 `StartNew(seed, fullCampaign:true)`。

## 作者与验证入口

1. 修改采纳参数后运行 `python tools/generate_formation_rules.py`，检查生成差异与受影响机制。
2. Unity入口 `YesterdayConvoy.Editor.FormationRosterTools.Install()` 保存新增Boss卡与单位引用，不改旧卡数值。
3. `YesterdayConvoy.Editor.FormationCampaignTools.Author()` 在编辑模式保存扩大的棋盘和全目录引用；`Validate()`检查场景、正式46人、23节点、16预案与36战备。地图工具由同一作者使用，不能在队友编辑场景时重建覆盖。
4. EditMode验证运营事务、全部角色技能入口和关键联动、守军曲线与资源清单；PlayMode验证实际场景、原作待机加载、购买/布阵/镜头和有限经济开局。
5. `YesterdayConvoy.Editor.BaselineTools.BuildWindows()` 构建本地Windows EXE。`-formationCampaignSmokeTest` 为正式入口的生产路径专项，`-formationSmokeTest` 为原五关无限金币样板专项；两种结果不能互相替代。

角色来源、真实缺失动作与加工验证见 [原作资源接入记录](art/FORMATION_ROSTER_V07.md)。运行素材和必要meta随源码本地提交，`Library/PreparedArt`是可重建缓存；正常运行不依赖项目外美术预览目录。当前交付不推送、不操作PR，不创建启动脚本、ZIP或Releases。

预设成型阵容、固定种子生产路径和自然购卡整局是不同的验证场景。完整自然通关分布、所有战备/徽章组合与长局性能仍须按真实试玩继续观察，不能从几个预设战斗推出最终平衡结论。
