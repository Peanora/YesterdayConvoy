# 《昨日圆车》项目指令模板

本文件是待复制的模板，不是当前目录的生效指令。建好真实 Unity 工程后，结合已有指令合并到仓库根目录 `AGENTS.md`；不要覆盖现有有效内容。检查并替换工程路径、精确 Unity 版本、入口和验证步骤，再用于实现。

2026-10-20：本文件保留早期建项内容供追溯。当前三人 Codex 协作请按根目录 [CONTRIBUTING.md](../CONTRIBUTING.md) 第1节初始化本地 AGENTS，并遵守该文档全部流程；不要把本模板的旧状态复制为当前工程事实，或用它覆盖现有 AGENTS。

## 开始工作

- 阅读当前用户任务、适用项目指令、`docs/GDD.md` 对应章节、`docs/STATUS.md`、当前任务卡和 Git 状态。
- 工程事实以实际文件、安装环境和运行结果为准。没有项目 / 文件时先核实，不虚构实现。
- 保留他人未提交改动；仅修改当前任务与必要相关修复。
- 项目仍处于 GDD v0.1 草案阶段。区分已定规则、建议、试验参数和待定选择；建议不能被登记为人类已确认。

## 项目现实约束

- 游戏名为《昨日圆车》，Unity 已获课程允许。
- 一人主导，两人辅助；当前排程按剩余 10 周、主导约 100 小时估算，投入可能更少。
- 基础目标为完整短流程；优先可玩、清晰、稳定，内容数量可以下调。
- Windows 单机与固定俯视 2D 是当前建议，实际项目采用前在 GDD / 决策记录注明。

## 已定玩法不可默改

- 战斗费用不自然回复；回费只能来自明确技能 / 规则。
- 不以倒计时判负。费用不足时先考虑场上单位、冷却、技能与待结算事件。
- 卡牌有有限部署次数和部署 CD；首领技能 CD 独立。
- 不设置首领专属数量上限，用经济与出现概率形成稀缺。
- 一角色可有多个标签，同场多个羁绊可同时生效。
- 怪物进入蓝门按配置扣防御值，强怪可扣更多，事件只结算一次。
- 核心成长为招募、升星、羁绊；不扩展肉鸽事件 / 遗物系统。
- “运气差可靠操作争取通关”是平衡目标，不承诺所有随机局面必胜。

## 日常自主工作与决定

- 对已授权的可逆实现、修复和验证继续推进，不逐步询问许可。
- 不清楚的常规实现选择采用最小方案并记录理由。
- 会改变已定核心玩法或造成难以回退的数据影响时，先明确具体选择与影响；继续不依赖该决定的任务。
- 草案建议可以用于配置化原型验证，标记假设；不得静默改成正式规则。
- 未被任务授权时不增加新机制、依赖、Unity 升级、外部付费服务或公开发布动作。

## Unity 与数据约束

- 锁定实际 Unity 精确版本、包清单和锁文件；根据安装包版本查询对应 API，不凭记忆升级依赖。
- 提交源码、配置和必要 `.meta`；不提交 `Library`、`Temp` 等缓存或本地日志。
- 保留 GUID；资源改名 / 移动优先在 Unity 中操作或用经验证的 Editor 工具。
- 配置数据只读，运行时状态单独创建；使用稳定 ID 区分卡实例、单位实体、单位种类。
- 所有战斗逻辑共享模拟时钟；暂停不推进部署 CD、技能 CD、移动和攻击。
- 费用、合成、购买和奖励采用原子 / 幂等操作，处理失败与重复请求。
- 胜负、场景生成和资源引用的更改必须运行相关验证。
- 不为原型引入 ECS、大型依赖注入、通用技能语言、联网或动态寻路。

## 并行与文件责任

- 同一场景、Prefab、配置资产、包清单只有一个写入者；接口变更先统一再分工。
- 确需并行时按当前用户授权与环境能力使用独立任务 / worktree，限定修改范围。
- 最终在集成工程重新编译、检查场景引用并运行；其他会话的口头结论不是验证证据。
- Unity Editor 生成 / 校验工具尽量幂等，重复执行不能复制资产或覆盖人工值。

## 验证与完成条件

- 本任务实际测试入口、编辑器路径和构建入口需从工程核实。尚无工具时先建立最小可执行入口，不杜撰方法名或命令。
- 根据变更运行相关配置校验、Edit Mode / Play Mode 测试和人工交互；重大流程变更需要独立构建检查。
- 优先测试部署事务、资源耗尽边界、暂停、独立首领 CD、羁绊去重、升星、穿门幂等、重试清理。
- 不为了提高测试数量复制实现细节；低影响文本可人工核对。
- 没运行 Unity、测试或构建时必须写“未运行”，区分静态推断、已运行事实和人工待验项。
- 连续两次无进展修复后先缩小复现，不继续扩散补丁。
- 每个完成任务更新实际状态和必要决策，给出改动、结果、限制与下一步。

## 第 7 周以后

- 第 7 周末冻结新增大机制；剩余时间优先试玩反馈、平衡、稳定性和交付。
- 最后一周不升级引擎 / 依赖、不全局重构；只做必要修复与受影响回归。
- 发布候选包记录对应提交、环境、目标平台和真实测试结果，第二台电脑离线核验。
