### 0.1 人类确认的四条开发原则（强制）

以下四条由用户于 2026-10-16 明确要求，适用于今后所有任务；不把本文件其他“建议”自动升格为已定规则。

1. **一个任务围绕一个可验收的玩家可见功能或小闭环。** 2026-10-16 用户修订：特别是前期，每次尽量写出一个能运行、能操作的功能，不按字段、类、极小技术步骤切碎工作。同一个闭环需要的逻辑、场景、相机、最小 UI 可一起交付，例如“一怪一塔、红门进攻蓝门的最初 Demo”。互不相关的大系统仍应拆分，目标失焦时提示；人类明确认可的范围优先。
2. **每个任务先阅读相关文档。** 文档是设计依据，不根据上次聊天猜测规则。先读根目录 `AGENTS.md`、`docs/STATUS.md`、本圣经相关章节及已有的相关任务卡，再检查实际文件和 Git 状态。
3. **每完成一个可运行功能就提交 Git。** Unity 的场景、Prefab、`.meta` 文件都必须正确纳入版本控制；`Library`、`Temp`、日志等缓存不提交。提交前运行相关验证；未运行或失败必须如实记录。本地提交不自动授权远端推送和发布。
4. **简明提供测试证据与系统连接说明。** 每次说明改动、实际检查/测试、未测项及风险，用几句话解释关键类和数据流。投入与风险匹配，不为简单功能堆编辑器工具、镜像测试、重复文档、逐文件指纹或截图系统。优先编译、实际场景与关键状态边界；已有验证按改动需要复用。常规任务简短更新 STATUS/QA 即可，无需每次生成新任务卡和证据 JSON。

前期执行顺序：先实现可观察闭环，再做必要验证与本地 Git 提交。只在确有重复劳动时增加工具，不把底层准备连续拆成多轮而没有可玩进展。旧任务板为参考依赖，不是必须逐条停下来等待新指令的最小粒度。

## 3. 三条设计支柱与验证问题

### 当前可玩闭环：M01交战与手动技力（2026-10-19）

用户点名克洛丝形象，并追问明确“本轮就要技力与手动释放”。克洛丝是高台远程干员，拥有生命/护甲/攻击范围，无阻挡概念（配置阻挡0）；放在现有高台(-1,1)，脚底高度0.35。维什戴尔是远程单位，约在进入克洛丝射程时开火，不以接触/阻挡为前提；有合法目标必须停步攻击，消灭目标后继续原路线，蓝门不是攻击对象。其他干员的通用可配置阻挡能力仍保留。范围按XZ平面距离，弹道延迟命中；源或目标死亡取消未命中效果。M01只有一名守军，强化炮击爆炸表现不等于完整多目标范围伤害系统。

`ManualDemo.asset`按2026-10-19最新演示要求改为DP12/守方生命1/部署2/次数1/CD2/HP100/速度0.75。原维什戴尔显示名改为“维维美”，内部ID和素材来源名保留。本关只能部署一只，穿门一次获胜，倒下且机会耗尽失败；此为当前Demo配置，不取消后续通用同卡多实体能力。只读`WisadelVsKroos.asset`试验值仍为：克洛丝HP180/攻击22/护甲3/范围3.2/间隔1/阻挡0；维维美普攻14/护甲2/范围3.2/间隔1.7；技力初始8/所需12/每秒1，手动开启六发强化炮击，单发攻击105/间隔3.2/范围3.8（技能不缩短普通攻击射程）。弹药耗完才重新回技力，技能不扣DP；每个部署实体独立保存状态。试验值不照搬原作精确平衡，也不确立正式首领身份。旧炮台/Bootstrap/纸片诊断已在随后清理任务中删除。

当前胜负各显示遮罩结算面板，包含结果、守方剩余生命、本场部署数量、技能释放次数和重新开始按钮。结算后不再接受底层拖动/技能输入；点击重新开始恢复准备状态，重置生命、费用、次数、CD、单位、干员、技能、暂停及速度，不发放尚未实现的金币或经验奖励。

技能参考保留“自动回技力、手动开启、六发弹药、慢速强化炮击”的辨识度；不在M01实现原作召唤物、残影或连锁附加机制。规则参考：[PRTS维什戴尔](https://prts.wiki/w/EW)、[PRTS克洛丝](https://prts.wiki/w/%E5%85%8B%E6%B4%9B%E4%B8%9D)。本地实现与原作数值有意区分。

操作：底部卡牌拖到红门松手部署，每次松手结束拖动；非法位置/CD/取消不扣费。暂停时合法松手立即部署并扣费/次数、设置CD，仍暂停且CD冻结。点场上角色或头顶金色就绪标志，在角色旁显示技能图标；选择期间0.03×继续（试验值），图标释放或空白取消后恢复原1×/2×，不自动放技能。完全暂停优先，需恢复后才能释放；重叠实体重复点选切换。空格暂停、右键/Esc取消选择；顶部1×/2×与静音，中途/终局“重新开始”清空本场。常规Player失焦暂停。攻击表现为独立持炮图+轻微后坐力、弹道/爆炸、受击闪色与死亡消散，未宣称完整逐帧动画。其他商店/合成/羁绊/多关经济本轮没有实现。

### 历史：单卡手动部署（2026-10-18）

沿用一张认可角色卡、一座防御塔和现有地图。点击底栏角色卡选中，在红门确认部署；第一次合法部署可直接开始作战，也可先点击“开始作战”观察空场。非法地点不开始战斗、不扣资源。每次成功部署消耗战斗费用和次数并进入冷却，同卡可以有多个独立实体；塔在射程内优先攻击沿路线走得最远者，同进度按生成先后稳定选择。

## 4. 核心循环与流程边界（建议）

### 4.1 玩家的重复行动

```text
观察下一关防守与路线
        ↓
用招募金币购买 / 刷新 → 合成升星 → 调整编队 → 查看同时激活的羁绊
        ↓
锁定本场编队与羁绊，获得本场战斗费用及部署次数
        ↓
观察防守动作 → 选择路线、卡牌、时机 → 扣费并生成怪物
        ↑                                      ↓
重新判断资源 ← 技能回费 / 冷却结束 / 击杀反馈 ← 移动、阻挡、攻击、技能
                                               ↓
                                    怪物穿门 → 防御值下降
                                               ↓
成功 → 获得金币 → 下一关招募；最终关成功 → 通关 → 开始新挑战
失败 → 结算并结束本次挑战 → 新挑战；中途可重新开始本关尝试
```

随机商店是构筑的一部分；不附加肉鸽事件系统。防守方由关卡作者预置，不实现对手自走棋运营 AI。

### 4.2 短流程结构

最终挑战目标为6–10关、约30–60分钟；采用作者固定关卡，同一地图模板调整防守。每场前准备运营，金币/等级/收藏跨场保留，战斗费用/次数/CD每场重置，新挑战重置构筑。2026-10-19最新决定：一关失败即结束本次挑战，覆盖此前失败后只换阵容反复重试的决定；中途觉得不对可以重新开始。中途重开按开战快照清理本场状态，不重掷商店/复制库存、不进行商店或装备运营。当前独立Demo没有跨关资源，重开即恢复全关初值。

胜负基础奖励金额相同，利息与胜负无关：赛后每10金币给1金币，最多5金币；连胜奖励另算，没有连败/击杀金币。失败仍显示本场基础奖和利息，但挑战已终结，不能带回同一关循环运营。中途重新开始不是已完成战斗，不产生奖励。委托设计的结算顺序先采用“结算前金币计算利息→基础奖与连胜额外奖励入账”，该时点为设计试验，非用户逐字定案；具体基础奖、连胜阶梯、经验表尚未完成模拟/实现。

不做局外永久属性成长、联网、账号、玩家对战、赛季、装备系统和完整长篇剧情。存档先保存关间进度；战斗中断点续玩属于后续项。

## 5. 已确认的六项核心规则（2026-10-16）

| 编号 | 问题 | 已定方案 | 原因 / 验证办法 |
| --- | --- | --- | --- |
| D01 | 无费时是否立刻失败？ | 场上结算完且不存在可恢复的部署机会后才资源耗尽失败 | 防止最后一个进门怪物、回费技能、冷却中的低费卡被误判 |
| D02 | 怎样从容思考？ | 战前无限观察；暂停允许拖放立即部署并扣费，战斗仍暂停；技能恢复后才执行 | 与实时部署相容；验证是否过于繁琐；不默认允许无限队列 |

## 6. 战斗规则规范（已定与建议分别标明）

### 6.1 资源与卡牌状态

两种货币完全分离：`Gold` 为招募金币，只用于战间商店；`DP` 为本场战斗费用，只用于部署和明确标价的战斗行为。已确认主动技能不消耗 DP；使用每实体初始技力、所需技力及回复规则，满技力后手动释放。技能不得自动替玩家施放。

每个编队卡实例包含 `cardInstanceId`、`unitId`、星级、部署费用、剩余次数、下次可部署时刻。`部署次数` 指“成功执行部署命令”的次数；一张群体卡生成多个实体，也只扣一次部署次数。实体另有 `entityId`，保存当前血量、位置、目标和技能状态。

本场初始化建议：`DP = initialDP`；卡牌次数由配置与星级计算；部署 CD 初始为就绪。**A10已确认：不返费、不撤退**。死亡/穿门不返还次数、穿门立即离场仍沿用当前原型规则。具体HP、攻击、护甲、费用、次数、CD、穿门伤害等由 Codex 配置化试验，用户试玩修改，不登记为最终平衡已冻结。

部署必须同时满足：战斗正在进行、费用足够、次数大于零、该卡冷却完成、入口 / 路线合法、生成点可用。失败请求返回可读原因，**不扣费、不扣次数、不进入冷却**。成功请求作为一个原子操作完成扣费、扣次数、设置 CD 和生成命令；快速连点也不能只扣一次却生成两次。

不设置首领专属并发上限。若需要防止单位重叠，使用短暂生成排队或入口位置检查；若设备压力需要总实体预算，先通过内容与对象复用控制，再由负责人决定，不能借性能名义加入首领配额。

### 6.2 时钟、暂停与信息

使用统一战斗模拟时钟驱动移动、攻击、部署 CD 和技能 CD。战术暂停与菜单暂停统一冻结；已确认课程版失焦自动暂停，重新获得焦点后手动恢复。暂停时所有战斗逻辑冻结，不允许挂在暂停页等回费或冷却。

已确认正常速度1×与2×开关，正常入口改拖动部署。点击角色打开旁侧技能面板时以0.03×继续（实现试验值）；施放成功/点空白取消/目标死亡关闭后恢复原速度，满技力头顶显示就绪标志。完全暂停优先保持0，暂停可查看但不施放技能。失焦取消拖动/面板并暂停，切回手动恢复。重开/终局清除交互状态；重叠实体重复点击切换。加速影响整个模拟时钟，不分别乘某些动画。不得用系统现实时间推进暂停中的战斗 CD。技能施放特效是表现，伤害 / 回费结算由逻辑事件负责。

### 6.3 路线、阻挡、攻击

**2026-10-18 A02–A07已确认：**

- 防守方就是干员，不再区分“可杀守军”和“不可拆防御塔”；全部干员都能被消灭。场景中的旧炮形外观与旧绑定已删除，不作为独立塔类继续扩展。
- 每种怪物拥有自己的攻击范围，范围内有干员即可攻击，**不要求必须先被阻挡才允许攻击**。X01=A：有合法目标就停步攻击，目标死亡/离开范围后继续前进；不采用边走边打。
- 每个干员具有自己的阻挡数，可以阻挡一定数量怪物；其余怪物继续走。X05已采用：普通怪每只占1名额、按到达顺序占位，干员或怪物死亡立即释放；重型多占格后置，不统一把所有干员设成挡1。
- 每关红门、蓝门均允许多个。X03=A：一个红门固定对应一条路线和一个蓝门，玩家选入口；不自动换道。X04=A：所有蓝门共用守方总防御，进入任意门均扣总值，归零胜利。当前单门实现仍待扩展，继续固定路点，不引入动态寻路。
- X05已采用：怪物优先攻击阻挡自己的干员，否则攻击范围内最近者；干员优先攻击自己阻挡的怪物，否则路径进度最前者；已有合法目标保持，平手稳定排序。
- X05已采用：伤害=`max(1, attack - armor)`。首期只有攻击与护甲，其他伤害体系后续扩展。

X02=A：干员死亡本场永久离场，重试才恢复，不做自动补员/复活。范围形状、攻击前摇与命中结算采用最小配置化实现并记录；飞行、隐身、嵌套召唤等不随基础交战扩展。

### 6.4 蓝门结算

单位第一次完成路线时产生唯一穿门事件：`defense = max(0, defense - gateDamage)`，随后销毁或回收实体。相同事件 ID 只能处理一次。较强单位允许有更高 `gateDamage`；召唤物、群体卡每个成员分别配置，防止一张卡意外造成成倍穿门伤害。

同一模拟步内先按已经确定的死亡 / 移动规则产生活体穿门事件，再结算防御值，检查胜利，最后检查资源耗尽。已在本步死亡的单位不能继续穿门。胜利成立后锁定状态，不再触发失败、重复奖励或延迟技能回调。

### 6.5 胜负、回费和死局

胜利条件：防御值降至 0。基础失败条件保留用户意图：**进攻资源耗尽，已经无法再组织进攻。** 不能实现为“当前 DP 小于最低费用就立刻失败”。

按照 D01 已确认的保守规则，按以下顺序判断：

1. 若已进入胜利 / 失败 / 主动放弃状态，不重复判定。
2. 若蓝门防御值为 0，胜利优先。
3. 若仍有场上进攻单位、待生成单位或待结算事件，继续运行：它们可能进门、击杀或触发回费。
4. 若没有以上内容，但存在“剩余次数 > 0、DP 足够”的合法卡，允许等待其 CD 或入口恢复，不判负。
5. 若本场存在已经承诺、将在未来结算的回费事件，先等待。主动回费若依赖首领，首领死亡后不能再假定它会施放。
6. 在场上清空、事件清空、无可恢复机会后，进入资源耗尽失败；显示 DP、剩余次数与原因。

“等待机会”不等于求解所有未来策略。基础内容限制下，空场时只有部署 CD、入口恢复和登记在案的延迟事件可等待，因此可保守、可靠地实现。以后添加全局回费、复活、召唤等机制时，必须同时扩展这个判定。

永久阻挡、零伤害互殴、无限治疗或可重复回费可能造成场上长期不清空。先用最低伤害、单位交互与内容验证检查死局；D06 暂不设回费累计上限，不得用旧草案偷偷补回限制。保留主动放弃、中途重新开始；失败结束挑战。长时间无进展只能提示，**不偷偷转成超时失败**。调试看门狗只输出异常信息。

### 6.6 必须通过的边界例

| 场景 | 正确结果 |
| --- | --- |
| DP 为 0，最后一只怪正在走向蓝门 | 继续，可能获胜 |
| DP 足够，唯一可用卡还有 5 秒 CD | 继续，CD 到点可部署 |
| 没钱，首领在场且回费技能将就绪 | 继续，能施放后再判断；不假设存在累计回费预算 |
| 空场，有钱，但所有卡次数用完 | 失败 |
| 空场，无钱、无事件、无回费来源 | 失败 |
| 本步穿门使防御值为 0，同时 DP 耗尽 | 胜利，奖励只发一次 |
| 暂停 30 秒后恢复 | CD、路径和回费量均不因现实等待而变化 |
| 两个首领同时存在 | 各自技能与头像正确；没有隐含首领上限 |
| 费用恰好够，连点两次 | 只有通过验证的命令生效，不出现负费用 |
| 强制重试 | 血量、阻挡、CD、次数、随机种子与快照正确恢复 |

## 7. 招募、升星、编队与羁绊（已定规则与待定参数分别标记）

### 7.1 商店

**已定：** 每次刷新提供五个购买位；招募费用分为 1–5 费；每种怪物初始固定 9 张基础牌，拥有该怪物的牌会减少其可抽库存。等级 1–10，采用 [SHOP-v0.1 的十级费用档概率表](proposals/SHOP-v0.1.md)，用户已逐项确认；不再采用按三场分别抽 1/2/3 档的旧表。

招募费表示商店档位/购买金币，与战斗部署 DP 分开配置；不把“5 费怪物”解释为战斗部署一定消耗 5 DP。首领通常较贵且难抽，但不是额外首领配额。

**已定的抽取与库存规则：** 每槽先按等级抽费用档，再按该档剩余基础牌数加权抽取；展示牌占用库存，避免同一刷新超抽。未购买牌在刷新时返库；出售 1/2/3 星分别返库 1/3/9 张，返库数不等于售出金币数。某费用档抽空后，只在本等级基础概率大于 0 且仍有库存的档中按原概率比例归一化，不解锁高费档。合法库存不足五张时只展示实际可抽数量并提示缺货，空槽不能购买。详细算式与边界见 SHOP-v0.1；这些是已确认设计，尚未实现或写入运行配置。

**2026-10-18 B组已定：** Gold为准备阶段金币，DP为战斗部署费用，不自动兑换；运营限准备阶段。付费刷新2金币，每关开始自动免费刷新，支持锁店以保留展示；锁店阻止自动换店，具体解锁交互可按最小方案。完全缺货不收费，少于五张按同价刷新并提示，不复制牌补满。普通经济局尽量避免买空全部卡池，极端强运经济局可例外；这是一项经济/内容预算验证目标，不是隐藏补牌机制。

出售金币：招募费为c时，1星=c、2星=3c−1、3星=9c−1；对应返库仍是1/3/9。开局1级，通关经验+金币买经验共同升级，升级保留当前五张、后续刷新使用新概率；10级是较难达到的上限，升级和追星争夺金币。备战10格，购买先入备战，满仓失败不扣钱，可确认购买+合成以腾位；已确认凑齐同种同星三张自动合成。

收入包含开局金币、利息、连胜金币和失败基础奖励；不加连败/击杀金币。胜负基础奖励相同，利息为赛后floor(金币/10)且最多5、与胜负无关；开局金币、基础奖励额、连胜阶梯、各级经验和买经验价格委托Codex设计试验，参考货币战争但不伪称完整照抄或已核验当前原作全部参数。旧8金币/刷新1金币/胜利6金币草案不能作为已定参数。锁店、奖励幂等与库存/可支配金币极值必须验证。

开局随机赠送低费角色并从相应九张库存扣除，数量/分布由经济方案明确；当前5费卡仅保留独立试验关，不作为正式开局保底。接受先用小卡池完成流程，不为此立即制作新怪物。

牌库按基础牌等价数记账：拥有 1 张 2 星占 3 张库存，1 张 3 星占 9 张；合成不凭空返库。持有某种怪物的 3 星就占满其全部 9 张，在仍持有期间不能再抽到该怪物。部署产生的战斗实体不是新的商店卡，不额外扣牌库；死亡/穿门不归还持有的卡。各怪物须满足 `可抽库存 + 商店占用 + 持有基础牌等价数 = 9`；购买把商店占用转入持有，不重复扣库存。

### 7.2 合成与编队

**已定：** 三张同种同星自动合成，1→2→3星，上限3星。升级卡继承原卡外观和位置；同名无论星级编队只允许一张，其他卡留备战。一张编队卡仍可按次数/CD部署多个战场实体。各星可分别增加次数、每次生成数或两者结合，按角色设计，不默认统一成长。具体属性/费用/CD/穿门/技能变化委托设计试验。

**已定：** 等级1–10，战前编队卡槽上限等于等级，不是战场实体数上限；所有编队槽均可放首领。B09已确认备战10格、购买先入备战；满仓时可明确确认购买+合成，完整事务成功才能扣金币，否则拒绝。自动合成已确认；稳定实现优先保留编队中的主卡，其次备战原位置，材料按获得顺序消耗并处理连锁升星。这是委托范围内的实现约定，事务失败不扣款。

同名无论星级编队只能一张，备战允许重复用于追星/转羁绊；按种类计数羁绊。上场阵容锁定后，本场不能购买、出售、升星或修改羁绊快照。

### 7.3 羁绊和流派

“标签”通常记录单位的原作组织、小队或族群；银狼的模拟接入另行标识，不改写原作身份。“流派”是玩家通过标签、单位技能、准备运营与部署节奏形成的作战方法。每种怪物可有多个标签，全部参与统计；某单位拥有 A、B 两标签，就同时为 A 与 B 各贡献一种。

已确认羁绊只取最高达成档、不叠加低档，大部分可作用于全部怪物，具体作用对象必须写明。战前按编队中不同单位种类锁定档位，备战、重复部署、死亡和穿门都不额外改变人数。

#### 7.3.2 银狼：羁绊接入、补丁与三星五费接管

**用户已确认的方向：** 银狼是指定乱入特例，固定五费方案；可以选择一个常规羁绊接入，后续升星继续选择；保留准备阶段补丁；达到三星五费后“接管《昨日圆车》”，解锁包括增加经验、提升等级在内的本局管理员玩法。这不是消耗技力的战斗技能，也不是只增加个人伤害。

当前采用的细案：1/2/3星分别有1/2/3个不同的接入槽；每次升星增加一次选择，并可调整一个旧选择。接入常规标签每种各计一种单位，不得重复叠同标签，不接入其他角色专属。选择保存在卡上，合成继承主卡而非合并材料卡的全部选择；备战不计，开战后锁定。自由付费重选尚未定案。

#### 7.3.3 落地约束

普通羁绊与专属的效果可以联动，但身份不能因玩法方便乱挂：塔露拉不计深池，泥岩小队不因历史归属自动计当前整合运动，巨像不计萨卡兹；“牧群”和合并“海嗣”的范围是本作归类改编。经济羁绊允许设计，不增加独立肉鸽事件/遗物系统，不新增击杀或连败金币。

新增召唤、转化、延迟事件必须接入资源耗尽判定；冻结/连锁设合理触发边界；培养与接管奖励不能因中途重开重复结算。所有战斗效果共享模拟时钟，角色实体技能继续独立保存技力。准备阶段资源与已实施特例分开保存，接管解锁也不能静默修改进行中的编队快照。细案附本轮文档检查记录，STATUS/QA存在其他任务既存修改，本轮按用户确认的隔离方案不编辑。

**计数例：** 编队甲[A,B]、乙[A,C]、丙[B,C]、丁[A,B]，则 A=3、B=3、C=2；三组同时生效。甲部署三次仍只按一种计数。备战卡不计数；同名甲不能重复占编队槽。

## 10. 运气与操作的平衡验证

目标拆开验证：

- 商店随机不应让一场正常教学关失去任何可执行方案。建议保底起始基础卡，并让低稀有度单位能覆盖抗伤、拆阵等必要职责。
- 在指定“弱阵容”测试快照中，较好的部署 / 技能操作能明显改善穿门结果；不声称所有弱阵容都能过所有关。
- 强构筑可以降低操作要求，但不应靠伤害数字遮住信息，让玩家不知道为什么变强。

每轮先做 3 个固定种子的普通阵容快照、2 个较弱快照、1 个强阵容快照。比较三种行为：随意点卡、按基础战术部署、较熟练地把握首领技能。记录胜负、剩余防御、费用利用、无效操作和等待时间；胜率不能替代玩家说明。

建议第一次请 3–5 位未参与设计的人试玩，记录是否能独立开始、是否看懂失败原因、是否提出另一种部署尝试。样本只能提供问题线索，不能据此宣称总体平衡。

如果所有测试都只需要开局把卡点完：增加需要分批处理的阻挡 / 伤害窗口。如果主要时间是在等 CD：缩短冷却、优化批次并提供加速；不要强加倒计时。若羁绊永远只有一套最优解：比较同预算的不同组合与关卡对局，不先增加标签数。

## 11. 数据与实现边界（建议）

配置数据与运行状态分开。配置可采用 ScriptableObject，运行时复制到状态对象，不直接修改配置资产。稳定 ID 用于卡牌引用、关卡配置、存档与日志，不依赖中文显示名。

| 数据 | 最小字段 |
| --- | --- |
| UnitDefinition | unitId、显示名、定位、是否首领、商店档位 / 买价、部署费、各星次数、部署 CD、每次生成数、HP、攻击、护甲、移速、穿门伤害、标签、技能 ID |
| SkillDefinition | skillId、目标规则、初始技力、所需技力、回复方式/速率、效果、失去目标处理；D06无累计回费上限 |
| SynergyDefinition | synergyId、阈值列表、是否累加、适用对象、效果与展示文字 |
| LevelDefinition | levelId、初始 DP、防御值、路线、防守配置、奖励、开战提示 |
| CardState | cardInstanceId、unitId、星级、剩余次数、部署可用时刻 |
| UnitState | entityId、来源卡实例、HP、路线进度、阻挡者、技能可用时刻、累计回费 |
| RunState | 存档版本、种子 / 随机状态、金币、等级/经验、收藏、编队、当前场次、商店占用与各怪物剩余基础牌数、开战快照；数据结构尚未实现 |

核心战斗逻辑尽量为可测试的普通 C#；Unity 组件负责输入、显示、场景引用、音效与对象生命周期。先使用少量直接接口，避免全局服务容器、大型行为树、ECS 或通用技能语言。

配置校验必须发现：重复 ID、缺失引用、负成本、无效路线、同卡标签重复、概率不归一、技能预算与结束判定不兼容。原型重复快照测试要求同一版本、同一操作序列产生稳定结果；不承诺跨平台逐帧完全确定。
