# 伤害跳字与状态反馈

本系统读取真实战斗结算结果，为伤害、治疗、护盾吸收显示跳字，为已生效的寒冷、冻结等状态显示短提示和持续中文标记。它不计算伤害、不制造 buff，也不改变角色数值、部署、索敌、路线或商店规则。

当前状态：源码已接入，独立 Roslyn 编译及检查记录见本节末；**Unity全量逻辑433项、相关图形52项已通过；Player验证尚待执行**。不能将此文档当作已通过实机验收的证明。

## 数据如何连接

`ManualBattle` 在实际扣血/治疗写入点产生只读 `CombatFeedbackEvent`。字段包括本局 `RunId`、递增序号、模拟时刻、目标类别与实体 ID、结算世界位置、事件种类及真实数量。

`CombatFeedbackPresentation` 仅消费这些结果，同目标同种结果按 0.15 模拟秒窗口合批；`CombatFeedbackView` 使用实际镜头、`TacticalViewport` 和 `ApprovedUi` 字体绘制文字。显示器不读取 `CombatShots` 估算伤害，也不以 Unity 相邻帧血量差代替结算事件。

- 怪物扣血在 `ApplyUnitHealthDamage` 写入后、阶段/死亡处理前记录，避免复起覆盖本次实际伤害。
- 干员扣血在 `ApplyDefenderLoss` 记录，包括保护者实际分摊；外层 `DamageDefender` 不重复记录。
- 羁绊盾和法术屏障分别记录实际吸收量；护甲减伤不会伪装成护盾。
- 怪物治疗走 `HealUnit`，干员实际治疗走 `RestoreDefenderHealth`；自疗、持续医疗及留声机调用同一写入入口。技能统计与回技力规则保留原调用关系。
- 过量伤害只显示真正扣掉的生命，过量治疗只显示实际恢复量。满血治疗、复起、改变最大生命、换形态和退场不会伪造治疗数字。

## 显示规则

- 伤害橙红，治疗绿，护盾吸收青。寒冷/冻结蓝，灼烧橙，恐惧/沉默紫。
- 模型事件只保留最近 256 条，屏显最多 96 条；窗口截断不补播过期战斗。每条约 1.05 模拟秒后淡出，不为每条数字创建 GameObject。
- 小于 0.1 的真实连续反馈显示 `<0.1`，避免显示 `+0` 或虚构 `+1`。
- 全部按现有 `PresentationClock` 播放：暂停冻结，技能选择的 0.03 倍同步；终局只推进表现尾段，最后反馈播完再展示原结算面板，不继续推进伤害结算。
- 更换战斗对象或 `RunId` 时清空旧显示。标签绘制避开商店、顶栏、卡栏和弹层；只使用 `GUI.Label`，没有点击控件、不消费输入事件，保持部署和角色技能点选。

## 状态覆盖及边界

干员覆盖寒冷、冻结、冰环停顿、神经损伤、灼烧和枷锁束缚；怪物覆盖停顿、恐惧、诱导、相关能力眩晕/沉默、灼烧、脆弱及现有数值护盾。

状态读取真实 `Until`、`DefenderShackled` 和 `UnitControlImmune`。新施加出现一次短提示，持续刷新时长不刷屏；失效、死亡或离场后移除。冻结期间用“冻结”替代同源寒冷。不可控怪物的无效控制计时不显示；塔露拉阶段锁定和隐藏火雨阶段不显示不执行的旧控制标记。

每个目标最多 4 个短标记，全屏最多 64 行；状态变化在有界模拟步采集，提示可能晚约 0.05 模拟秒。凝视等专用对象表现暂不纳入这一最小标记列表，也没有新增原本不存在的暴击或伤害类型提示。本实现不是通用技能/buff系统。

## 验证

新增 `CombatFeedbackTests` 8 项 EditMode 测试：实际伤害/过量、两种吸收与扣血区分、干员不双记、真实治疗、霜星复起不算治疗、寒冷转冻结/暂停/重开、免控、事件只读有界以及密集显示上限。

新增 `CombatFeedbackSceneTests` 2 项 PlayMode 测试：真实场景绑定/暂停/重开，以及跳字时拖动部署和角色技能点选。

接入时补丁锚点和 `git apply --check` 通过，保留已提交塔露拉阶段与九条羁绊场景改动。使用现有 Unity 引用独立 Roslyn 编译 Runtime、Editor、Editor.Tests、PlayMode.Tests 四个程序集，均退出 0；这没有启动 Unity，也没有执行测试方法。第一次仅重编 Runtime 后的 Editor.Tests 失败来自旧 Editor 引用未包含新 `GameSceneCatalog`，随后按 Runtime→Editor→两种测试程序集重编通过。
