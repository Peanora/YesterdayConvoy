## 2. 核心循环草图

```text
观察敌方阻挡、射程、路线和蓝门防御
          ↓
用金币招募、升星、编队 → 形成一个或多个羁绊组合
          ↓
选择怪物、入口和部署时机
          ↓
消耗战斗费用 / 部署次数，触发该卡部署冷却
          ↓
怪物移动、接战；玩家把握首领技能时机
          ↓
看到血量、阻挡、技能、回费和穿门结果
          ↓
重新评估剩余资源与防守变化 ──────→ 再次选择部署 / 技能
          ↓
蓝门防御归零 → 奖励金币 → 下一关招募与编队 → 再次进攻
          ↓
最终关通过 → 通关 → 新挑战

进攻资源耗尽 / 主动放弃 → 显示原因 → 原快照重试，或重新构筑新挑战
```

这里描述的是玩家行动与系统反馈之间的循环，不用“菜单—游戏—结束界面”代替玩法循环。金币与战斗费用是两种不同资源。

## 3. 首个可玩目标草稿

**待验证假设：** 在没有自然回费和战斗倒计时的情况下，有限费用 / 次数下的部署顺序和首领技能时机，能形成值得反复尝试的策略选择。

| 项目 | 最小定义 |
| --- | --- |
| 玩家能做什么 | 看防守；点击卡牌和入口部署；选择已部署首领释放技能；暂停 / 恢复；重试 |
| 最少内容 | 一条固定路线、蓝门、阻挡者、远程防守者、快怪、耐打小怪、有限回费首领 |
| 可见反馈 | 费用、剩余次数、两类 CD、血量、阻挡关系、技能效果、穿门减防御、胜负原因 |
| 一次尝试结束 | 蓝门防御归零成功；场上与事件清空且无未来部署机会后资源耗尽失败；允许主动放弃 |
| 怎样重置 | 恢复同一个开战快照，重置费用 / 次数 / 冷却 / 防守 / 单位 / 随机状态 |
| 不在这次做 | 商店、升星、羁绊、正式美术、多个地图、完整存档、剧情 |
| 负责人 | 主导者：规则与集成；辅助 A：边界复现；辅助 B：操作录像与结果记录。姓名待填写 |

完成判据分两层：

1. **实现完成：** 上述输入和反馈可实际运行，边界判定无误，发布测试包能打开。
2. **假设初步成立：** 同一编队与防守配置下，不同部署 / 技能策略产生可观察结果差异，试玩者能说出差异原因，至少愿意尝试一种改法。

如果功能已完成但玩家仍只是无脑点完卡牌，则“实现完成，玩法假设未成立”，回到阻挡、技能窗口与单位职责进行修改。不能把原型完成等同于好玩已证明。
