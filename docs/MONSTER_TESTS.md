## 怎样进入

1. Unity打开`Assets/_Game/Scenes/InitialDemo.unity`后Play，或启动最新本地Windows EXE，首先显示“选择测试怪物”。
2. 本机装有批准资源时，左侧可玩样板有维维美、塔露拉、源石虫，点击对应“进入测试”。每次进入都重置费用、部署次数、守军、角色、技力、技能、弹道和速度。
3. 进入后仍是底部卡牌拖到红门部署，满技力点角色/技能释放；暂停拖动等规则保持。
4. 测试中点击左下“返回怪物选择”；胜负结算页也有同名按钮。返回即结束并清理本场，不保存半场状态。重新开始按钮仍重开当前怪物测试。
5. 右侧列出其余38个待制作候选（未装源石虫包时为39个），可以按名字筛选；这些只是清单，不是已实现角色，不能点击进入空测试。

当前样板包括本机塔露拉和源石虫的原版媒体；它仍是[本地可选资源](art/TALULAH-ORIGINAL-INTEGRATION.md)，普通公开克隆缺包时回退到已有技术样板并记日志。菜单不会假定队友已经取得原版媒体。

## 连接和兼容性

`MonsterTestSelection.cs`是`ManualBattleController`的局部类：建立只读目录、绘制选择页，并通过`TryEnterMonsterTest(cardId)`和`ReturnToMonsterTests()`管理界面状态。现有`SwitchTrial(bool)`保留兼容，诊断和旧测试可以显式进入原样板。

选择页打开时，正常Update/Tick、拖动和部署入口被拦截，模拟速度为0；选卡/空格不会在底层偷偷开战。返回调用原重开和表现初始化，清理实体/弹道/拖动/技能焦点并让火雨在随后渲染帧归零。选择页文字和按钮用原字体与IMGUI，不新增AI图片或角色资源。

`ManualBattleInteraction`保留结算按钮的完整按下/松开匹配：不能在别处按下后，抬到“返回”上就误触。测试中返回、结算返回和旧重开共用完整状态清理；进入另一种怪物不继承守军数量或旧拖动。

仅独立的自动回归命令行参数跳过正常启动菜单，兼容原Player取证入口。`-monsterSelectionSmokeTest -demoEvidenceDir <目录>`专门验证选择页并输出真实ScreenCapture（包含HUD），不把该诊断称为人工鼠标通关。

## 队友怎样增加一个已完成的怪物测试

先按[怪物待做与协作清单PR #5](https://github.com/Peanora/YesterdayConvoy/pull/5)认领、确认美术和接口范围；不要直接复制塔露拉的技能配置冒充新怪。配置/ID和资源必须真实可用。

1. 按当前已批准接口准备自己的`UnitDefinition`、`CardDefinition`、`EngagementDefinition`及`ManualBattleDefinition`；一份测试定义只绑定一个怪物。招募金币与部署DP分开。
2. 将已验证的`ManualBattleDefinition`资产放到任一`Resources/MonsterTests/`子目录，建议统一为`Assets/_Game/Data/Resources/MonsterTests/<StableId>.asset`。这是新增约定路径，当前还没有预建该空目录或新怪配置；通过Unity创建并保留所有必要.meta。
3. 程序启动时自动发现这些资产，不用修改主场景，也不用再为每个入口写一个布尔切换。主导者仍须审批/协调新增配置的引用与共享接口。
4. CardId必须唯一，不能与内置维维美/塔露拉重复。显示名与候选名单一致时，自动替换相应“待制作”条目；新名字则增加新的可玩条目。
5. 缺少必要配置、Snapshot校验失败、重复CardId或缺少当前要求的动作帧，会记录`MONSTER_TEST_CONFIG_REJECTED`且不开放入口，不会用无效配置启动。
6. 源石虫已支持无主动技能和近战呈现（[安装/配置](art/ORIGINIUM-SLUG-INTEGRATION.md)）；独立伤害类型/状态及正式多卡编队接口仍未完成。本入口没有解决这些底层依赖；遇到不支持的规则先协调，不能塞入假技能帧或默改玩法通过校验。

资源加载只取单卡测试配置，不自动创建商店牌、羁绊或其他怪物。各作者可维护自己的独立测试资产，避免多人写同一份主场景或入口数组。
