## 核心循环草图

完整游戏的规划循环（招募、升星、羁绊、关间流程尚未实现；手动技力技能已接M01）：

```text
观察下关干员、路线与守方防御
    ↓
用金币招募/刷新/买经验 → 合成升星 → 编队并确定羁绊
    ↓
初始化本场战斗费用DP、部署次数和CD
    ↓
选卡与红门 → 消耗DP/次数并进入CD → 怪物沿固定路线推进
    ↑                                      ↓
调整下一次部署/技能 ← 看见接战、受击、阻挡与穿门反馈
                                           ↓
                                  穿门削减守方总防御
                                           ↓
胜利 → 结算金币/经验 → 下一关准备 → 最终关成功 → 新挑战
失败 → 本次挑战结束；中途可重新开始当前尝试，之后可开启新挑战
```

金币用于准备阶段买卡/刷新/升级；DP是本场部署费用，不自然回复。胜负基础奖励相同；利息每10金币得1、最多5，与胜负无关。失败结束本次挑战，中途重开不领奖；经济系统尚未实现。

当前已经运行的最小循环：

```text
拖动底部卡牌 → 红门松手 → 扣费并生成怪物 → CD结束后再次拖放；暂停也可立即部署，战斗仍暂停
                 ↑                                 ↓
             调整出兵/技能 ← 克洛丝高台远程攻击，维什戴尔停步还击，技力满手动炮击
                                                   ↓
                  防御归零胜利 / 资源耗尽且空场失败 → 重新挑战
```

当前已用克洛丝替换正常入口的炮形火力点，接入生命、护甲与死亡离场；当前克洛丝为高台远程，不阻挡；维什戴尔停步还击，手动技能击杀后继续原路线。只做一名干员样板，多门尚未接入。

- 工程根目录：`E:/珍贵资料/昨日圆车`，包含Assets、Packages、ProjectSettings。

## AI建议与核验取舍记录

选取一个已有真实案例，而不是为课程重新编造过程：

1. 玩家反馈：行走时后方黄色条/高台盖到人物前面。
2. 核验：检查角色排序，并用真实GPU读取720/1440画面。旧排序在1440高度为负，复现后方涂装覆盖人物。
3. 修正与再核验：改为分辨率无关的正值排序、地表不透明材质；实景仍发现高台切脸，继续降低装饰高台并加入出错路段回归。
4. 最终证据：两种分辨率穿透像素均为0，正常前景实体仍遮挡；构建和实机结算通过。证据与先失败后修正记录在QA，不把一句AI“完成”当核验。
5. 取舍：保留地图与动作方向，修正表现，不靠让人物永远显示在所有物体前面掩盖错误。人类观感验收仍与自动测试分开。

当前数据连接：只读关卡/交战配置→ManualBattle保存费用/CD/单位/干员/SP/弹药与结算→ManualBattleController及其ManualBattleInteraction分文件连接拖动/角色点选/HUD与统一速度→DemoSpriteVisual/纸片动画/EngagementView呈现运动、持炮与特效。运行时不改配置资产，暂停/2倍速共享模拟时钟。
