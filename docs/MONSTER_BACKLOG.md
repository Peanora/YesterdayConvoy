## 2. 推荐制作顺序

| 顺序 | 本轮内容 | 可验收结果 |
| --- | --- | --- |
| P0 | 源石虫、猎狗、士兵、弩手、术师、重装防御者，共6种 | 基础近战、远程、承伤及不同身体结构能在样板中正常表现 |
| P1 | 泥岩小队掷能者、泥岩小队践行者，加泥岩巨像支援 | 为第一条“养巨像”构筑路线准备素材；巨像召唤/培养另做功能任务 |
| P2 | 其余感染生物、游击队与爱国者 | 补充单位差异和军令协同路线，不同怪物可连接多条羁绊 |
| P2 | 雪怪小队与霜星 | 在寒冷/冻结/碎冰规则及状态接口确认后制作 |
| P2 | 牧群、深池、萨卡兹，以及其余五费专属 | 依赖转化、火种、承契等单独实现的机制 |
| P2 | 海嗣、银狼 | 特殊行为/形态及完整准备运营依赖较多，后置 |

P0/P1共8张普通卡是推荐首批规模，不是现在同时开8个开发任务。每人每轮认领一个清晰目标，例如“弩手美术预览通过”或“源石虫按已批准配置完成战斗样板”。确认预览与接入可以是前后两个交付阶段。

## 4. 召唤物与五费专属另列

召唤物不自动成为永久商店卡，也不能增加羁绊种类数或递归制造无限单位。

- [ ] S01 泥岩巨像：独立召唤、跨关培养、承伤/重击/范围震击阶段；不占普通卡池九张库存。
- [ ] S02 整合运动援军：近战/弩手表现，有限次数；数值、次数和穿门扣防御规则另行确认。
- [ ] S03 牧群转化体：弱宿主、原单位死亡后的接力表现，禁止再次转化。
- [ ] S04 守墓石像：地面承伤/远程支援两种方向，仍按已定规则支付DP部署。

## 5. 每只怪物怎样才算交付

### A：美术预览通过

- [ ] 确认单位原名、身份、原作参考及本作职责；没有凭名字擅改阵营。
- [ ] 先在Unity工程外提供卡面/概念图、战斗形象和待机/移动/攻击动态预览；有技能的展示技能动作及必要特效。
- [ ] 同时展示放大细节和预计游戏尺寸，沿用正向斜俯视2.5D镜头；角色有脚底/身体接触点。
- [ ] 使用当前已确认的精致二次元与暗黑工业幻想方向，角色比例/绘制/动作对标原作；不得自行回到被否决的大头漫画或像素混搭方向。
- [ ] 无腿单位使用符合结构的蠕动/漂浮，多足单位按结构运动；普通行走不能仅用图片平移或整体弹跳冒充。
- [ ] 记录来源具体页面、作者、许可、下载文件或生成工具；检查Alpha、边缘和方向，不把黑底当透明。
- [ ] 干宸骅明确确认这一版预览，记录确认日期和实际文件版本。普通“开始做”或代码测试通过不能替代看稿确认。

这一阶段可以独立交付，不因未实现商店而阻塞。无法获取完整动作时，标出缺口和可达质量，不能把分镜标成动作视频。

### B：战斗样板通过

- [ ] 已取得本次接口、文件及场景写入范围确认；使用批准的预览资源。
- [ ] 新怪拥有自己的稳定ID、卡面/战斗资源及已确认的战斗参数；不共享可变实体状态。
- [ ] 在约定样板中完成部署→移动→发现合法干员停步攻击→击杀继续移动→穿门/死亡→重开。不主动攻击等特殊单位须先确认例外，按其真实行为验收，不能强塞普攻。
- [ ] 待机、移动、普攻、技能（若有）、受击和死亡可辨认，动作不拖动逻辑根节点；生命条/技力条与模型一致。
- [ ] 暂停、0.03倍速技能选择和2倍速都读取同一模拟时钟；技能若有移动锁，目标死亡后仍完整收势。
- [ ] 报告修改文件、真实测试、未测内容、已知问题，以及配置→运行时实体→表现的连接。

无主动技能的怪物不强塞一个六发技能来满足旧样板字段。通用配置不支持时，提出最小接口需求，由主导者协调解决。

### C：正式流程接入通过（依赖系统完成后）

- [ ] 进入正确费用档和九张基础牌库存，开局保底/商店出现规则符合设计。
- [ ] 备战、同名编队唯一、三张同种同星自动合成、出售返库均正确；星级数值有配置。
- [ ] 多标签按战前编队不同种类统计，备战/重复实体/死亡/穿门不改变本场羁绊档位。
- [ ] 单卡部署次数/CD、实体技力/技能独立；不同怪物不会串用攻击/生命/资源。

角色状态须注明“A已过、B待做、C依赖未就绪”等，不能用“已完成”掩盖只做了图片或单卡样板。

## 7. 程序接入前的真实架构与依赖

美术任务此时可以继续；程序接入若依赖该前置目标，应标“等待公共配置接口”，不要私自发明第二套Manager或改全局参数凑效果。商店、升星、羁绊、状态系统分别作为后续闭环，不要求每位角色作者重复造系统。

原作辨识度例外必须另列：酸液源石虫削甲、冰爆源石虫/寒冷联动、泥岩掷能者物理伤害、囊海爬行者不主动攻击等，不能用通用普攻糊过去；涉及新增伤害类型/不主动攻击等基础规则时先协调。塔露拉不计深池，巨像不计萨卡兹，泥岩小队不自动计当前整合运动，W/维什戴尔不拆成两种凑羁绊。

## 8. 文件放哪里、怎样避免冲突

- 未确认美术：工程外工作区，例如仓库旁`YesterdayConvoy-ArtPreviews/M08-Archer-v1/`，包含图片、短视频、来源与处理说明；不要提前覆盖Assets。
- 确认后素材：`Assets/_Game/Art/Characters/Monsters/Normal/<StableId>/`；精英/首领按确认身份放对应Elite/Boss目录，不仅凭价格判定。卡面、图标、特效依现有Art目录分别放置。
- 新配置优先使用`Assets/_Game/Data/Units/`、`Data/Cards/`现有目录；字段与绑定方式以届时已合入接口为准。
- 独立样板场景/Prefab需先认领具体文件及审批写入范围。默认不修改`InitialDemo.unity`、现有共享Prefab、Packages/ProjectSettings；独立分支不等于文件锁。
- 角色说明与试玩结果可放`docs/monsters/<StableId>.md`；该目录是建议新增约定，目前不代表已存在或已有生成工具。新建目录放说明文件，避免空目录无法跟踪。
- 只有一人维护同一共享配置、场景、Prefab或资源清单。各作者提供本角色来源记录，由约定写入者统一更新[资源清单](art/ASSET_MANIFEST.csv)和[Credits](art/CREDITS.md)，不要三人同时修改同一个CSV。
- Unity生成的必要`.meta`与资源一起提交，保留GUID；不复制Library/Temp，不把整个工程互相覆盖。

原版角色/贴图公开可见不等于允许原文件公开再分发。来源许可明确允许的素材可按许可提交；权利未确认的原作提取资源/派生图集及包含它们的预览只留本地，由主导者协调合法可用的交付方式，不能自动塞进公共PR。记录原始页面和生成/修改过程，不只写“网上找的”。
